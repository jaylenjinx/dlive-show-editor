# RevEngPlate1 — RackUltra Plate Reverb Designer

Source: live Director 2.12 scenes 11–96, generated by automating Director offline (no show export needed — checked directly against Director's live `Scenes/StageBox` folder, then saved as `RevEngPlate1.tar.gz`). UFX2 is `AHFX` engine `1d00` (Plate Reverb Designer), the same 262-byte payload shape used by the Spaces engines (`1c03`/`1c04`).

`P CTL 1` / `P CTL 2` (11/12) are byte-identical outside the scene name, giving a clean baseline. Inside each sweep, every adjacent pair changes only the target field; a few sweep-boundary pairs change two adjacent fields at once because a restore and the next sweep's first value land in the same scene (see [Writer policy](#writer-policy)).

## Type preset — decoded, read-only

`state +85` selects one of eleven library presets (Chrome, Dark Vox, Ambience, Steel, XL Plate, Classic, Bright, Vocal Focus, Impact, Dark, Small Plate) shown in Director's **Type** picker. Two values are proven: `Vocal Focus = 0x60`, `Bright = 0x00`. Selecting a preset rewrites many bytes across the record at once — the same hybrid-state problem documented for the Spaces Reflection Model and RackUltra compressor models — so the editor keeps this byte read-only.

## Linear controls — `raw = 0x8000 + 16 × value`

Every sweep point matched the formula exactly, the same coordinate the Spaces engines use.

| Control (Director) | Offset | Range | Sweep points |
|---|---:|---|---|
| Pre Delay | `+30..31` | 0–170 ms | 0, 85, 130, 170 (40 is the original) |
| Diffusion | `+36..37` | 0–100 % | 0, 25, 50, 75, 100 |
| Size | `+38..39` | 0–100 % | 0, 25, 50, 75, 100 |
| Shape | `+40..41` | 0–100 % | 0, 25, 50, 75, 100 |
| Modulation Speed | `+66..67` | 0–100 % | 0, 25, 50, 75, 100 |
| Modulation Depth | `+68..69` | 0–100 % | 0, 25, 50, 75, 100 |
| Width | `+112..113` | 0–100 % | 0, 25, 50, 75 (100 is the original) |
| Position | `+120..121` | 0–100 % | 0, 25, 50, 75, 100 |

Ranges are Director's clamps, found by typing out-of-range values. The editor writes continuous integers inside them.

## Decay Time — log-time, `+56..57`

The existing `time_log` coordinate (`decode_raw`'s `10^((raw−17874)/5958)`, fed the value in milliseconds even though Decay is displayed in seconds — the same behaviour already documented for Spaces Decay) reproduces these anchors closely, with the same small rounding seen there:

| s | Raw |
|---:|---:|
| 0.1 (min) | `91B1` |
| 1 | `8BA3` |
| 5 | `9BE8` |
| 10 | `A2E9` |
| 20 | `A9EB` |
| 30 (max) | `AE04` |

`1`, `5` and `10` s are byte-identical to the Spaces Decay Time anchors, confirming both engines share one Decay coordinate. The writer uses these exact anchors, matching the Spaces policy.

## Output LF/HF Cut — PEQ log-frequency coordinate

| Control | Offset | Range | Anchors |
|---|---:|---|---|
| Output LF Cut | `+70..71` | 20 Hz–1 kHz | 20=`29CB`, 50=`4196`, 100=`5396`, 200=`6596`, 500=`7D62`, 1k=`8F62` |
| Output HF Cut | `+72..73` | 1–20 kHz | 1k=`8F63`, 2k=`A162`, 5k=`B92D`, 10k=`CB2D`, 20k=`DD2D` |

Every anchor is byte-identical to the Spaces LF/HF Cut tables — this is the same canonical PEQ frequency coordinate used throughout the format. The writer uses these exact anchors.

## Echo taps 1–6 — same layout as Spaces, L1 and R2 independently proven

The Director **Echoes** overlay is visually identical to the Spaces Echoes page (same six-tap graph, same Left/Right/Time/Gain/On/Off side panel, same 0–200 ms graph axis), and the byte layout turns out to be identical too: consecutive 4-byte blocks (`[time_hi, time_lo, gain_hi, gain_lo]`) starting at `state +88`, in record order **L1, L2, L3, R1, R2, R3**, with each tap's On/Off byte in a separate run starting at `state +133` (2-byte stride).

| Echo | Tap | Time | Gain | On/Off |
|---:|---|---:|---:|---:|
| 1 | L1 | `+88..89` | `+90..91` | `+133` |
| 3 | L2 | `+92..93` | `+94..95` | `+135` |
| 5 | L3 | `+96..97` | `+98..99` | `+137` |
| 2 | R1 | `+100..101` | `+102..103` | `+139` |
| 4 | R2 | `+104..105` | `+106..107` | `+141` |
| 6 | R3 | `+108..109` | `+110..111` | `+143` |

Only **L1 and R2** were independently swept (28 scenes: 5 time points, 5 gain points, an On/Off toggle pair, each, plus the global section toggle). The other four taps are assumed to share the layout by analogy with the proven Spaces engines and L1/R2's own agreement, but are not independently tested — flagged in the editor's evidence note.

### Time

`raw = 0x8000 + 16 × ms`, identical to every other time field in the format. Anchors `0, 50, 100, 150, 200 ms` matched exactly on both L1 and R2.

### Gain

Unlike the Spaces engines (which show small ±2–3 code low-byte offsets on typed anchors), Plate's echo gain is an **exact continuous formula**:

```text
raw = 0x8000 + round(dB × 256)
```

Confirmed at five points on both L1 and R2, byte-for-byte:

| dB | Raw |
|---:|---:|
| −39 (near min) | `5900` |
| −20 | `6C00` |
| −10 | `7600` |
| 0 | `8000` |
| +10 (max) | `8A00` |

Director's numeric floor is **−39 dB**; typing or dragging to −40 dB switches the display to a non-numeric **`Off`** state instead (not explored further — recovering from it just requires typing a value back in the −39…+10 range). The editor's writer covers the continuous **−39…+10 dB** range using the proven formula, rather than exact anchors, because the formula reproduced every tested point exactly.

### On/Off

`10 = On`, `00 = Off`, same convention as Spaces.

## Echoes section — global bypass, `state +131`

`00 = In` (default/active), `10 = Out` (bypassed) — proven with a controlled toggle pair. This is the inverse of the usual `toggle_10_on` convention used elsewhere (there, `10` means on); Plate's Echoes section byte means the opposite, so the editor labels it explicitly rather than reusing that shared encoding name.

## Writer policy

Writers are guarded to engine `1d00` and the 262-byte AHFX payload:

- linear fields: continuous integer, per the ranges above
- Decay: exact anchors only
- LF/HF Cut: exact anchors only
- Echo 1–6 time: continuous `0…200 ms`
- Echo 1–6 gain: continuous `−39…+10 dB`
- Echo 1–6 On/Off and the Echoes section bypass: the two observed states
- Type preset: read only

A handful of adjacent scene pairs in the sweep show two fields changing together — a restore step for the field just finished landing in the same scene transition as the first value of the next sweep. These are expected and match the pattern already documented for the Spaces batches; the underlying anchor values above were extracted directly from the stored scene bytes, not inferred from the merged diffs.

## Generation notes

Scenes were generated by a scripted Director session identical in method to the Spaces batches: Scene Manager row select → Store → rename, parameters entered through Director's ctrl-click numeric entry, and read back by macOS Vision OCR. One recovery was needed mid-run: repeatedly re-clicking a tap's position on the Echoes graph to reselect it (to verify/update believed state) nudged its Gain down a few dB each time, eventually crossing the −39 dB floor into the non-numeric `Off` display. The fix was to stop re-clicking the graph between edits — Director remembers which tap is selected across closing and reopening the Echoes overlay, so each tap only needs to be selected once.
