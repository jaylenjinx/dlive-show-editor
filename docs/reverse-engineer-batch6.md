# ReverseEngineer6 — RackUltra 480 Medium / Spaces echo taps

Source: `ReverseEngineer6.tar.gz`, generated by driving dLive Director 2.12 (offline) automatically rather than storing scenes by hand. UFX1 is `AHFX` engine `1c04` (Spaces / 480 Medium) with the 262-byte payload shape from [batch 5](reverse-engineer-batch5.md).

Scenes 101–174 hold the sweep. `CTL 1` / `CTL 2` (101/102) are byte-identical outside the scene name, which gives a clean baseline. Every adjacent pair inside a sweep changes only the target AHFX field outside the scene name.

## Echo tap layout

The Director **Echoes** page shows six taps: three Left and three Right. They are stored as six consecutive 4-byte blocks from `state +96`, in record order **L1, L2, L3, R1, R2, R3**. Each tap also has a one-byte On/Off in a separate 2-byte-stride run from `state +127`.

The earlier Echo 1 and Echo 2 (batch 5) are L1 and R1. The editor keeps those names and numbers the rest Echo 3–6 = L2, R2, L3, R3.

| Echo | Tap | Time | Gain | On/Off |
|---:|---|---:|---:|---:|
| 1 | L1 | `+96..97` | `+98..99` | `+127` |
| 3 | L2 | `+100..101` | `+102..103` | `+129` |
| 5 | L3 | `+104..105` | `+106..107` | `+131` |
| 2 | R1 | `+108..109` | `+110..111` | `+133` |
| 4 | R2 | `+112..113` | `+114..115` | `+135` |
| 6 | R3 | `+116..117` | `+118..119` | `+137` |

The same `+127` / `+133` On/Off positions were already known for the `1c03` Spaces engine, so the tap layout is probably shared across Spaces variants.

## Time

All six taps independently prove the batch-5 transform:

```text
raw = 0x8000 + 16 * time_ms
```

Typed anchors were `0, 50, 100, 150, 200 ms` on L3, R1, R2 and R3, and `0, 100, 150, 200 ms` on L2 (`0x8000`, `0x8320`, `0x8640`, `0x8960`, `0x8C80`).

The first L1/L2 scenes were set by dragging rather than typed. They show that the stored resolution is **1/16 ms** and that Director's display truncates: the scene shown as `52 ms` stores `0x8344` = 52.25 ms, `99 ms` stores `0x863C` = 99.75 ms, and `149 ms` stores `0x895A` = 149.625 ms. Those pairs show up as writer-check mismatches in `dlive_re.py validate`, which is expected. The editor writes whole milliseconds only, over the directly established `0…200 ms` range.

## Gain

Director labels this control **Gain**; batch 5 called it Feedback. Typed anchors are identical on every tap:

| dB | Raw |
|---:|---:|
| −40 (min) | `5800` |
| −20 | `6BFD` |
| −10 | `75FD` |
| 0 | `8003` |
| +10 (max) | `8A00` |

Dragged values fit the same offset-binary `/256 dB` coordinate (`6BEC` = −20.08 dB shown as −20.1, `75E2` = −10.12 shown as −10.1, `7FD8` = −0.16 shown as −0.2). Typed round values carry a ±3-code low-byte offset, so the writer stays on the exact typed anchors above.

## On/Off

`10 = On`, `00 = Off`. Each tap's Off/On pair changes only its own byte.

## Writer policy

The writers are guarded to engine `1c04` and a 262-byte AHFX payload, and cover all six taps:

- time: continuous integer ms, `0…200`
- gain: exact anchors `−40, −20, −10, 0, +10 dB`
- On/Off: `10` / `00`

## Generation notes

The scenes were generated by a scripted Director session: Scene Manager row select → Store → rename, with parameters entered through Director's ctrl-click numeric entry and read back by macOS Vision OCR. `tools/director_automation.py` now uses ctrl-click entry by default (see [tools/director/README.md](../tools/director/README.md)).
