# RevEngRD1 — RackUltra Rhythm Delay (Simple mode)

Source: live Director 2.12 scenes 11–42, generated by automating Director offline and checked directly against Director's live `Scenes/StageBox` folder (no show export needed), then saved as `RevEngRD1.tar.gz`. UFX3 is `AHFX` engine `2d00` (Rhythm Delay), the same 262-byte payload shape as the Spaces and Plate engines.

`RD CTL 1` / `RD CTL 2` (11/12) are byte-identical outside the scene name. Inside each sweep, every adjacent pair changes only the target field, plus one unexplained byte described in [Unmapped byte](#unmapped-byte-151) below.

Rhythm Delay has two very different UIs. **Simple** mode (mapped here) exposes Tempo, Global Tap, Dotted/Triplet, Interval, Number of Repeats, an Amplitude shape/percentage, Auto Pan, Feedback and Drive. **Advanced** mode replaces the right two-thirds of the panel with a variable-length per-tap pattern editor (add/remove taps, each with its own position/gain/pan, a shared Bar Length, and a Dry Repeat toggle) — a different, open-ended data structure that is **not** mapped by this batch.

## A note on automation reliability

Early runs of this sweep produced impossible data: adjacent sweep values sharing identical raw bytes (e.g. Feedback −20 and −10 both storing the same word). The cause was the automation's Simple/Advanced toggle occasionally mis-detecting the current mode and silently flipping into Advanced, where the same screen coordinates land on unrelated Advanced-mode controls (or a graph with no numeric entry at all) instead of Simple mode's Feedback/Drive/Amplitude knobs — so several "edits" in a row did nothing, and the previous scene's value got re-stored under a new name. All affected scenes (Feedback, Drive and Amplitude) were regenerated after hardening the mode check to verify the switch landed before proceeding, and every value below was re-confirmed byte-for-byte in the corrected run.

## Tempo — new coordinate, `state +28..29`

```text
raw = round(60000 / BPM)
```

This is the delay time in milliseconds for one beat at that tempo (`60000 ms / 60 s × 1 beat`). Proven exactly at four points:

| BPM | Raw |
|---:|---:|
| 33 (min) | `071A` |
| 200 | `012C` |
| 500 | `0078` |
| 1000 (max) | `003C` |

Director's range is `33…1000` BPM, found by typing out-of-range values (below 33 clamps to 33; there is no visible upper clamp below 1000, and values above 1000 are rejected outright). The editor writes the continuous formula over this range.

## Feedback — clean continuous formula, `state +30..31`

```text
raw = 0x8000 + round(dB × 256)
```

Unlike the Spaces engines' typed-entry quantisation noise, this is an **exact** match at every tested point, on both this batch and the corrected re-run:

| dB | Raw |
|---:|---:|
| −39 (near min) | `5900` |
| −20 | `6C00` |
| −10 | `7600` |
| 0 | `8000` |
| +5 (near max) | `8500` |

Director's numeric floor is **−39 dB**; typing or dragging to −40 dB switches the display to a non-numeric **`Off`** state, the same behaviour already documented for Plate's echo gain. Not explored further. The editor's writer covers the continuous **−39…+5 dB** range.

## Auto Pan, Drive, Amplitude — linear, `raw = 0x8000 + 16 × value`

The standard percentage coordinate used throughout the format, confirmed 0–100 at 25-point steps on all three:

| Control | Offset |
|---|---:|
| Auto Pan | `+148..149` |
| Drive | `+144..145` |
| Amplitude | `+38..39` |

**Amplitude is not an independent effect send.** Changing it also proportionally rewrites several other bytes in the record (`+98..99`, `+104`, `+122..123` at this record's current tap count), which are the individual gain values of the Advanced-mode tap pattern — Amplitude is a shape/scale control over that pattern's gains. Writing the proven `+38..39` word is safe and reproduces Director's own behaviour exactly (every write in this batch changed only `+38..39` plus those same scaled tap-gain bytes, never anything else), but the scaled bytes themselves stay read-only since the Advanced pattern editor isn't mapped.

## Global Tap Tempo — `state +147`

`10 = On`, `00 = Off`, proven with a controlled toggle pair.

## Groove (Dotted / Triplet) — one shared enum, `state +35`

Director's **Dotted** and **Triplet** are not independent booleans — they are two buttons for a single three-state control, confirmed by controlled toggles:

| State | Raw |
|---|---:|
| Triplet | `00` |
| Straight (neither pressed) | `10` |
| Dotted | `20` |

## Unmapped byte `+151`

This byte changes on almost every scene in this batch — sometimes `00→10`, sometimes `10→00` — with no correlation to which control was actually edited. It looks like a transient "recently edited" or similar internal flag rather than a real parameter. Left preserved/unmapped; every controlled pair in this batch resolves to exactly the target field plus this one incidental byte.

## Not mapped

- **Type preset** (the Director library dropdown) — not swept.
- **Interval** and **Number of Repeats** — these controls did not respond to the same click/ctrl-click/drag interactions used successfully elsewhere on this page during manual probing; not swept.
- **Advanced mode's per-tap pattern** (position, gain, pan per tap; Bar Length; Dry Repeat) — a variable-length structure, out of scope for this batch.

## Writer policy

Writers are guarded to engine `2d00` and the 262-byte AHFX payload:

- Tempo: continuous `33…1000` BPM
- Feedback: continuous `−39…+5 dB`
- Auto Pan, Drive, Amplitude: continuous `0…100%`
- Global Tap, Groove: the observed enum states
- Everything else in this record: read-only

## Generation notes

Scenes were generated the same way as the Spaces and Plate batches: Scene Manager row select → Store → rename, parameters entered through Director's ctrl-click numeric entry, read back by macOS Vision OCR. This session also hardened the underlying automation for future batches: the display's backing-scale factor (Retina vs non-Retina) and screen-scan coordinates are now auto-detected rather than assumed, since the physical monitor Director ends up on can change between sessions.
